# UTF-8 编码损坏：现状、成因与修复方案

> 本文档记录仓库内 3 个文档的编码损坏问题。写下来的原因：这是**不可逆的数据
> 损失**，且其中一个文件连 git 历史都救不回来；不留档，下一个人只会看到一堆
> 莫名的 `?` 而不知道发生过什么。

## 1. 现状（2026-08-21 实测）

| 文件 | 损坏处数 | 有干净历史底本？ |
|---|---:|---|
| `docs/DATA_SOURCE_STRATEGY.md` | 498 | ❌ 全部历史版本均已损坏 |
| `docs/OPERATIONS.md` | 404 | ✅ 提交 `6823d18` |
| `docs/OBSERVABILITY.md` | 214 | ✅ 提交 `6823d18` |
| **合计** | **1116** | |

全仓其余 476 个文本文件均为合法 UTF-8（`python scripts/check_encoding.py` 实测）。

## 2. 损坏形态

每个 3 字节 UTF-8 中文字符的**第 3 字节被替换成 `?`（0x3F）**，前 2 字节完好。
实测 403 处替换为 `?`、1 处为 `.`。

```
原文：恢复。   ->  E6 81 A2  E5 A4 8D  E3 80 82
损坏：恢复?    ->  E6 81 A2  E5 A4 8D  E3 80 3F
                                            ^^ 被吃掉的字节
```

`?` 是编码转换失败的典型占位符 —— 说明某次写回时用了非 UTF-8 编码（很可能是
GBK 或系统默认 ANSI），无法表示的字符被替换。**这一步不可逆**：原字符信息
已从文件里消失。

git 历史显示损坏出现在 `a9f2c8b` 之后，潜伏了 3 个提交才被发现。

## 3. 为什么不能"重写一遍就好"

前 2 字节固定后，第 3 字节的合法取值只有 64 种，所以每处损坏是**从一个有限
候选集里挑一个字**，不是自由创作。实测各前缀的候选数量：

| 前缀 | 候选字符 | 全仓样本 | 主项占比 |
|---|---|---:|---:|
| `efbc` | `（），：；？` | 16402 | 25.6% |
| `e294` | `─│┌┐└┘├┤┬┴` | 6339 | 77.9% |
| `e380` | `、。《》「」` | 6086 | 49.8% |
| `e286` | `←↑→↓↔` | 1025 | 92.5% |

`efbc` 那一行是关键：`（）：，` 四个字符各占 26/25/20/19%，**按频率猜的错误率
接近 3/4**。把猜测直接写进文档，比留一个显眼的占位符更糟 —— 读者无法分辨哪句
是原文、哪句是机器编的，文档从此不可信。

因此本项目的修复原则是：**只填能证明的，不填猜的**。

## 4. 三个工具

| 脚本 | 作用 |
|---|---|
| `scripts/check_encoding.py` | 拦截非法 UTF-8 文件，已挂 pre-commit 钩子；`--strict` 连已知损坏一起判失败 |
| `scripts/repair_utf8_docs.py` | 分轮修复，只做可证明的推断；`--worklist` 导出选择题清单 |
| `scripts/verify_utf8_repair.py` | 机械校验修复结果：未损坏正文必须逐字节一致，每处修复的字必须落在候选集内 |

### 修复分四轮

1. **底本对齐**（432 处）：`OPERATIONS.md` / `OBSERVABILITY.md` 在 `6823d18`
   有干净版本，用 difflib 序列对齐**精确恢复**，不含猜测。
   注意两个实测踩到的坑：占位符本身对不上底本（要看左邻居反推）、
   损坏版是 CRLF 而底本是 LF（要先规范化，否则对齐全废）。
2. **语料唯一前缀**（26 处）：扫全仓未损坏文档统计每个前缀实际用过哪些字，
   若该前缀在整个项目里**只对应一个字**，填它是推断而非猜测。
3. **结构约束**（24 处）：架构图框线 `┌────┐`，横线只能接横线 —— 结构上唯一。
   刻意不用"选最高频"，理由见 §3。
4. **人工选择题**（剩 634 处）：`--worklist` 导出 `docs/_utf8_worklist.json`，
   每条给出候选集与前后 40 字上下文；填好 `pick` 后用 `--choices` 合并，
   越出候选集的答案会被拒绝。

当前进度：**1116 处已定 482 处（43%）**，634 处待人工判定。

### 用法

```bash
python scripts/repair_utf8_docs.py                    # 报告，不写盘
python scripts/repair_utf8_docs.py --worklist         # 导出选择题清单
python scripts/repair_utf8_docs.py --apply            # 写 .partial（占位符标记待定处）
python scripts/repair_utf8_docs.py --choices docs/_utf8_worklist.json --apply
python scripts/verify_utf8_repair.py <损坏文件> <修复后文件>   # 校验修复合法
```

`--apply` 在仍有待定处时**只写 `.md.partial`，不动原文件** —— 半成品不入库。

## 5. 防复发

`.pre-commit-config.yaml` 新增 `check-encoding` 钩子，任何非法 UTF-8 的文本
文件都会被拦下。3 个已知损坏文件登记在 `check_encoding.py` 的 `KNOWN_BROKEN`
里，默认只警告不阻断（否则这道检查一上线就把所有提交卡死）。
**修复完成后请从该清单删除对应条目 —— 清单为空是目标状态。**
