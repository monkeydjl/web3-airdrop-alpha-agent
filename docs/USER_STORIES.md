# 用户故事与用例

> 配套文档：FRONTEND_SPEC.md、API_SPEC.md、TASK_BREAKDOWN.md。本文档从用户视角描述系统功能的使用场景，供产品验收与测试用例设计参考。
>
> 适用阶段：MVP → V2 → V3。每个故事标注优先级与目标版本。

---

## 1. 用户角色定义

| 角色 | 描述 | 典型场景 |
|---|---|---|
| **空投猎人（Airdrop Hunter）** | 核心用户，寻找早期项目参与空投 | 每日查看 FARM 项目、跟踪参与进度 |
| **研究员（Researcher）** | 深度分析项目，辅助决策 | 查看 agent 分析详情、对比多项目 |
| **运维/管理员（Admin）** | 系统维护、配置管理 | 触发 run、处理 quarantine、查看告警 |

## 2. MVP 用户故事（W1-W4）

### 2.1 Dashboard 浏览

#### US-001：查看今日推荐项目
- **作为** 空投猎人
- **我希望** 打开 Dashboard 就能看到今日 Top 项目列表
- **以便** 快速决定今天参与哪些项目

**验收标准**：
- [ ] Dashboard 加载时间 < 2s
- [ ] 默认按 score 降序展示
- [ ] 每个项目卡片显示：name、sector、score、label（FARM/WATCH/IGNORE）
- [ ] FARM 项目用绿色标识、WATCH 黄色、IGNORE 红色（V2 后按 DESIGN_TOKENS.md；MVP 单页 HTML 可暂用灰色区分）

**优先级**：P0 | **版本**：MVP

---

#### US-002：筛选项目
- **作为** 空投猎人
- **我希望** 按 label/sector/stage 筛选项目
- **以便** 只关注我感兴趣的赛道或标签

**验收标准**：
- [ ] 支持 label 多选筛选（FARM/WATCH/IGNORE）
- [ ] 支持 sector 单选筛选（下拉列表）
- [ ] 支持 stage 筛选（testnet/mainnet/ideation）
- [ ] 筛选条件实时生效，无需点击"应用"按钮
- [ ] 筛选条件显示在顶部标签栏，可单独移除

**优先级**：P0 | **版本**：MVP

---

#### US-003：搜索项目
- **作为** 空投猎人
- **我希望** 通过项目名称或赛道搜索
- **以便** 快速找到特定项目

**验收标准**：
- [ ] 搜索框支持模糊匹配（名称包含即可）
- [ ] 搜索响应时间 < 500ms（前端本地过滤）
- [ ] 搜索无结果时显示空状态提示
- [ ] 清空搜索框恢复完整列表

**优先级**：P1 | **版本**：MVP

---

### 2.2 项目详情

#### US-004：查看项目完整分析
- **作为** 研究员
- **我希望** 点击项目卡片查看完整 agent 分析
- **以便** 了解评分背后的详细依据

**验收标准**：
- [ ] 项目详情页显示：score、label、confidence、reason 列表
- [ ] 显示 4 个 agent 分析结果（Narrative/Team/Risk/Tokenomics）
- [ ] 每个 agent 结果可展开/折叠
- [ ] 显示数据来源（sources + fetched_at）
- [ ] 显示评分权重版本（weight_version）

**优先级**：P0 | **版本**：MVP

---

#### US-005：查看评分理由
- **作为** 空投猎人
- **我希望** 看到每条评分理由的具体依据
- **以便** 判断是否值得信任该评分

**验收标准**：
- [ ] reason 列表每条显示人类可读文本
- [ ] 正向信号绿色前缀（+）
- [ ] 负向信号红色前缀（-）
- [ ] 缺失数据标记黄色前缀（!）

**优先级**：P0 | **版本**：MVP

---

#### US-006：查看置信度
- **作为** 空投猎人
- **我希望** 看到评分的置信度指标
- **以便** 判断该评分是否可信

**验收标准**：
- [ ] confidence 0-1 显示为百分比或环形图
- [ ] confidence < 0.5 时显示警告图标
- [ ] 悬停显示"X/4 个分析 agent 成功"

**优先级**：P1 | **版本**：MVP

---

### 2.3 手动触发分析

#### US-007：手动触发分析
- **作为** 空投猎人
- **我希望** 手动触发一次分析 run
- **以便** 获取最新项目数据

**验收标准**：
- [ ] Dashboard 顶部有"刷新"按钮
- [ ] 点击后显示加载状态
- [ ] 分析完成后自动刷新列表
- [ ] 分析失败时显示错误提示
- [ ] 分析进行中时按钮禁用（防重复点击）

**优先级**：P0 | **版本**：MVP

---

#### US-008：重算单个项目评分
- **作为** 研究员
- **我希望** 对单个项目触发 re-score
- **以便** 用最新数据重新评估

**验收标准**：
- [ ] 项目详情页有"重算评分"按钮
- [ ] 点击后显示加载状态
- [ ] 完成后更新该项目 score/label
- [ ] 失败时显示错误原因

**优先级**：P1 | **版本**：MVP

---

### 2.4 赛道洞察

#### US-009：查看赛道热度排行
- **作为** 空投猎人
- **我希望** 看到各赛道的热度排行
- **以便** 选择当前值得关注的赛道

**验收标准**：
- [ ] Insights 页面显示赛道热度列表
- [ ] 每个赛道显示：heat_score、项目数、趋势箭头
- [ ] 支持按热度/项目数排序
- [ ] 点击赛道跳转到该赛道项目列表

**优先级**：P1 | **版本**：MVP

## 3. V2 用户故事（W5-W11）

### 3.1 用户反馈

#### US-010：提交项目反馈
- **作为** 空投猎人
- **我希望** 对项目提交"有用/无用"反馈
- **以便** 帮助系统改进评分质量

**验收标准**：
- [ ] 项目卡片有"👍 有用" / "👎 无用"按钮
- [ ] 点击后按钮状态变化（已反馈）
- [ ] 可选填写备注（最长 500 字符）
- [ ] 反馈提交后显示感谢提示

**优先级**：P0 | **版本**：V2

---

#### US-011：事后标注项目结果
- **作为** 空投猎人
- **我希望** 事后标注项目是否真空投
- **以便** 为权重校准提供数据

**验收标准**：
- [ ] 项目详情页有"标注结果"入口
- [ ] 选项：airdropped / not_airdropped / pumped / dumped
- [ ] 标注后显示"已标注"状态
- [ ] 支持修改标注

**优先级**：P1 | **版本**：V2

---

### 3.2 数据质量

#### US-012：查看数据来源
- **作为** 研究员
- **我希望** 查看项目的数据来源详情
- **以便** 验证数据可靠性

**验收标准**：
- [ ] 项目详情页"数据来源"折叠面板
- [ ] 显示每个来源名称、reliability、fetched_at
- [ ] 来源按 reliability 排序
- [ ] 未命中的来源显示"未命中"

**优先级**：P1 | **版本**：V2

---

#### US-013：查看 Agent 执行记录
- **作为** 研究员
- **我希望** 查看每个 agent 的执行耗时与状态
- **以便** 诊断评分异常

**验收标准**：
- [ ] 项目详情页显示 agent 执行时间线
- [ ] 每个 agent 显示：状态（成功/失败/回退）、耗时
- [ ] 失败的 agent 显示错误类型
- [ ] LLM 回退时显示"AI-enhanced"标记

**优先级**：P2 | **版本**：V2

---

### 3.3 通知与推送

#### US-014：新 FARM 项目通知
- **作为** 空投猎人
- **我希望** 有新 FARM 项目时收到通知
- **以便** 第一时间参与

**验收标准**：：
- [ ] 系统检测到新增 FARM 项目时触发通知
- [ ] 通知渠道：浏览器通知（MVP）/ Telegram（V2）
- [ ] 通知内容：项目名称、score、sector
- [ ] 点击通知跳转到项目详情

**优先级**：P1 | **版本**：V2

---

### 3.4 审计与合规

#### US-015：查看操作审计日志
- **作为** 管理员
- **我希望** 查看系统的操作审计日志
- **以便** 追踪谁在何时做了什么

**验收标准**：
- [ ] Admin 页面显示审计日志列表
- [ ] 每条日志显示：action、user、detail、ip、时间
- [ ] 支持按 action/user 筛选
- [ ] 日志不可删除（只读）

**优先级**：P2 | **版本**：V2

## 4. V3 用户故事（W12+）

### 4.1 个性化

#### US-016：个性化项目排序
- **作为** 空投猎人
- **我希望** 系统根据我的偏好排序项目
- **以便** 优先看到我可能感兴趣的项目

**验收标准**：
- [ ] 用户偏好从历史反馈推断
- [ ] 偏好维度：赛道、风险偏好、参与频率
- [ ] 排序在默认 score 排序基础上加权
- [ ] 用户可关闭个性化（恢复默认排序）

**优先级**：P2 | **版本**：V3

---

#### US-017：项目画像与历史
- **作为** 研究员
- **我希望** 查看项目的完整历史画像
- **以便** 了解项目从早期到成熟的演变

**验收标准**：
- [ ] 项目详情页显示历史时间线
- [ ] 时间线节点：stage 变化、score 变化、label 变化
- [ ] 支持查看任意历史快照
- [ ] 显示关键事件（如 mainnet 上线）

**优先级**：P2 | **版本**：V3

---

### 4.2 多钱包策略

#### US-018：生成参与 checklist
- **作为** 空投猎人
- **我希望** 系统生成项目的参与步骤清单
- **以便** 按步骤完成交互提高空投概率

**验收标准**：
- [ ] FARM 项目详情页显示"参与 checklist"
- [ ] checklist 包含：交互类型、预估成本、频率建议
- [ ] 支持标记步骤完成状态
- [ ] checklist 基于项目特征动态生成

**优先级**：P2 | **版本**：V3

---

#### US-019：多钱包管理建议
- **作为** 空投猎人
- **我希望** 系统给出多钱包参与的建议
- **以便** 优化资金分配与风险控制

**验收标准**：
- [ ] 显示建议钱包数量（基于 sybil_difficulty）
- [ ] 显示每个钱包建议资金量
- [ ] 显示风险提示（多账号关联风险）
- [ ] 纯建议性质，不执行任何链上操作

**优先级**：P3 | **版本**：V3

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标 | 测量方式 |
|---|---|---|
| Dashboard 首屏加载 | < 2s | Lighthouse |
| API 响应时间（P95） | < 500ms | Prometheus |
| 单次 run 完成时间 | < 60s（50 项目） | 日志 timestamp |
| 并发用户支持 | ≥ 10（MVP） | 负载测试 |

### 5.2 可用性

| 指标 | 目标 |
|---|---|
| 系统可用性 | ≥ 99%（V2+） |
| 数据新鲜度 | 每日至少 1 次成功 run |
| 故障恢复时间 | < 1h（V2+） |

### 5.3 安全

| 需求 | 说明 |
|---|---|
| 密钥管理 | 仅 env 注入，不入库 |
| 输入校验 | 所有 API 入参 Pydantic 校验 |
| 速率限制 | 60 req/min/IP（V2） |
| 审计日志 | 所有关键操作留痕 |
