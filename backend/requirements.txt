# 可观测性：链路追踪（OpenTelemetry）—— **可选**，见下方说明
#
# 为什么单独拆到 requirements-otel.txt：
#   1. 这 7 个包此前写在本文件里，但**本地从未安装过**（实测 pip 查询：
#      opentelemetry-* 全部 "未安装"），也**没有任何测试覆盖**
#      （`pytest -k "otel or tracing"` → 2504 deselected，0 个用例）。
#      也就是说：它们被声明为必需依赖，却从未被验证过能装上、能跑通。
#   2. app/tracing.py 对缺包做了优雅降级：`except ImportError` 后走 no-op
#      tracer。实测 `OTEL_ENABLED=true` 且缺包时，应用**正常启动**、
#      /health 返回 200，只打一条 `tracing.unavailable` 警告日志。
#      所以它们对主流程不是必需品。
#   3. 默认 `OTEL_ENABLED=false`（docker-compose.prod.yml），
#      不开 observability profile 时装了也不会被用到。
#
# 要用链路追踪时（配合 compose 的 observability profile：
# otel-collector + jaeger）：
#   pip install -r requirements.txt -r requirements-otel.txt
